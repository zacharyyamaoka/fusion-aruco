Auto-sizing ArUco tags on a face: three proposals

Once you tag a face, nearly every number should be computed. Three ways to get there (you set the marker size; you set the count; you pick from ranked layouts), each run on five real faces by real code, and one recommendation.

Companion doc: docs/proposal_aruco_autosize.md. Nothing here is implemented yet; the “today” section is what the add-in on this branch does.

TL;DR

Recommendation: Proposal 1 (size first) with Proposal 3's ranked list as a “Layout” dropdown under it. You type one number (two for ChArUco); the add-in fills the face with as many markers as fit at that size, centred, quiet zone guaranteed, dictionary and first id chosen. The default size is your own tube rule (pattern = 70 % of the short side) rounded to the nearest 0.5 mm, and it reproduces both of your boards: 5 × 1 at 26.5 mm on the 38.1 mm tube (you built 27.1), 5 × 1 at 35.5 mm on the 50.8 mm tube (you specified 36.0); ChArUco on the 38.1 tube comes out 19 / 14 mm squares / markers, your L2 exactly.

Are we doing it already? Partly, and backwards. Today the dialog takes columns × rows and computes the marker size to fill the face (that is Proposal 2's model, minus rounding and minus the checks). The marker size itself is not an input on a face at all. Nothing is rounded to 0.5 mm, the dictionary is never auto-picked, and a face that is not a rectangle is measured by its vertex box only. Effort to get to the recommendation: about three days, almost all of it pure Python with tests.

What we do now

The ArUco Tag dialog on this branch (ArucoMarkers/aruco_commands.py) and the sizing it runs (markers.fit_board), described exactly:

  • Inputs: target (sketch profile or planar face), type, dictionary, first id (next free), columns, rows, tile thickness (profile only), black thickness and whether it is inlaid / raised / half (depth_m, raise_m), quiet zone in modules, rotate, name. Cell growth (grow_m, off by default) is a separate option.
  • Face measure: aruco_tags.face_frame: x along the longest straight edge, W × H = the extent of the face's vertices along x / y. Holes and notches are invisible to it; a face with no straight edge and no vertices (a circle) measures 0 × 0.
  • Sizing: fit_board fills the box: single = min(W, H) · n / (n + 2q); grid = the largest L with gap 0.2 L and quiet zone q modules for the given cols × rows; ChArUco = the largest square with marker 0.75 S. No rounding (the stored length is rounded to 0.1 µm). The pattern is centred in the box.
  • Checks: the info text warns when a module is under 1.2 mm and when the ids run off the dictionary. Nothing stops an absurd count (1 × 40 on a tile).
  • Not done: no marker-size input on a face, no 0.5 mm rounding, no dictionary auto-pick, no minimum-count sense (a “grid” of 1 × 1 is accepted), no fit test against the real face.

What Zach asked for

“I want to make sure its very ergonomic that once we tag the face that a lot of the parameters for the size of the marker are being autocomputed. … I think the prior aruco studio we have could be a reference.. in terms of like spacing around etc... I think generally what I want to control is the marker size. and checker size (if its charuco board)... all the other spacing and stuff I think can then be autocalculated off those. it should always kinda fit within the face. markers shouldn't ever be overlapping. Lets have smart good defaults. I prefer rounding to nearest .5 mm for the defaults on the marker sizes.”

— 2026-10-07; and earlier that day, on OpenCV-tutorial ratios: “good defaults always a good idea”.

  1. Tag a face, get numbers. After the face is picked, the dialog is already valid.
  2. The marker size is the control (plus the checker size for ChArUco). Spacing, counts, margins follow.
  3. Always inside the face.
  4. Markers never overlap.
  5. Smart defaults, rounded to the nearest 0.5 mm.
  6. The Studio's spacing as the reference: its boards are ChArUco with checker, marker and margin in mm; its suggest_board_grids ranks the grids that fit an envelope. Your tube boards (fiducials.board_for_tube) are the other reference: marker ≈ 0.7 × tube, gap = margin = (tube − marker)/2.
  7. OpenCV-tutorial ratios as defaults: gap = 0.2 × marker, ChArUco marker = 0.75 × square.
  8. (implied) Valid for OpenCV every time, and serial ids keep working when a board's count changes.

The geometry every proposal shares

All three proposals compute the same things from the same face box; they differ only in which number you hold. Lengths in mm; n = modules per marker side (6 for 4×4, 7 for 5×5); q = quiet zone in modules (default 1).

quiet Q = q · L / n (grid, single) gap s = max(0.2 L, L / n) (grid) cols = ⌊(W − 2Q + s) / (L + s)⌋ rows = ⌊(H − 2Q + s) / (L + s)⌋ (grid) cols = ⌊W / S⌋ rows = ⌊H / S⌋ (ChArUco) extent = cols·L + (cols−1)·s | cols·S margins = (W − extent_w)/2, (H − extent_h)/2 invariants: margins ≥ Q (grid/single) · margins ≥ 0 (ChArUco) · s > 0 · L < S · ids < capacity rounding: defaults → nearest 0.5 mm, then re-check; if rounding UP broke the fit, step down 0.5 sizes derived from a count → DOWN to 0.5 mm (they are maxima) limits: module ≥ 1.2 mm (0.4 mm nozzle) · grid ≥ 2 markers · ChArUco ≥ 2×2 squares (OpenCV), ≥ 4 corners advised

Hard invariants, checked by code, not by eye: every candidate is run through aruco_board.check_spec (the gate that mirrors what cv2 refuses: a grid with separation 0, a ChArUco under 2 × 2 or with marker ≥ square, ids past the dictionary) and through the margin test above. A layout that fails either is never offered; the dialog says why.

Dictionary auto-pick. Keep the family (4×4 unless you choose otherwise, since fewer bits means bigger modules at the same marker size) and pick the capacity from the design: smallest of 50 / 100 / 250 / 1000 holding ids already used + this board + headroom, with headroom = max(2 × need, need + 10) as markers.suggest already does. Examples: a 5-marker strip in an empty design → DICT_4X4_50; the same with 40 ids in use → DICT_4X4_100; a 13-marker ChArUco with 60 in use → DICT_4X4_250. Growing capacity never reprints anything: 4X4_50 is the first 50 patterns of 4X4_1000.

What does not change the footprint. depth_m / raise_m (inlaid vs raised black) and grow_m (cell growth, clamped to the black square) are thickness and manufacturing choices; none of them moves a marker's side or the layout. Two things they do touch: a raised layer lifts the detector frame by raise_m (already handled in detector_frame), and an inlay deeper than the body under the face is a hole — a check the dialog could add (face body thickness vs depth_m), not a sizing input.

When the face is not a rectangle

Honestly: the face box is all we measure today, and all any proposal sizes from. What is computable beyond it:

  • Detect it. face.area vs box area: a rectangle is 1.0; a plate with a hole 0.9; an L-shape 0.75; a disc 0.785. Below 0.98 the dialog says “not a rectangle: sized to the 120 × 70 box, checked against the face”.
  • Test the candidate against the real face. Fusion answers “is this point on the face” (face.evaluator.getParameterAtPoint + isParameterOnFace). Sample the pattern outline (corners, edge midpoints, every marker's four corners) and the quiet-zone outline; any point off the face means the layout does not fit. Then shrink: P1 steps the size down 0.5 mm, P2 drops a column or row, P3 filters its list. A hole in the quiet zone passes (as the demo tile's mount hole does); a hole under a marker fails. On a disc this finds the inscribed square (d/√2) in a few steps.
  • Not computable (cheaply): the best placement. We centre in the box; for an L-shape the right spot is off-centre. The honest answer is the existing one — sketch a rectangle where you want the tag and use ArUco Extrude, or split the face.

Proposal 1 — Size first: you set the marker, the face fills

You set: Marker size (one number). ChArUco adds Checker size. Both carry an auto button that restores the default. Dictionary and first id default to auto. Everything else is under Advanced, pre-filled.

Computed: cols × rows (as many as fit), gap, quiet zone, margins (leftover split, pattern centred), dictionary, ids. The info chips show the layout and the readable range.

Default size (your rule, generalised): single L = 0.7 × short side. Grid: k markers across the short side span 70 % of it, k = 1 on a strip (long/short ≥ 3), 2 on a plate: L = 0.7·short / (k + 0.2(k−1)). ChArUco: k squares fill the short side, k = 2 on a strip (your L1/L2), 3 on a plate (so ≥ 4 inner corners); marker = 0.75 S. All rounded to the nearest 0.5 mm, then checked; if rounding up lost a marker or broke the fit, step down.

Can't fit: a typed size that overhangs (or leaves a “grid” with one marker) is clamped to the largest 0.5 mm step that works, and the chip says so in orange: clamped: 30.0 mm does not fit, using 15.5 mm. Nothing is silently accepted and nothing is rejected: the dialog is always valid.

Not a rectangle: the fit test above, shrinking the size. The chip adds “sized to the box, shrunk for the hole”.

Pros, cons, effort, ids

Pros
  • Exactly the words: one number in, a board out.
  • The default is the calibrated tube rule, so existing boards re-create themselves.
  • Always valid; clamping explains itself.
  • Pure function; 20 unit tests cover it.
Cons
  • You cannot ask for “2 × 3” directly; you move the size until the count is what you want (P3 fixes that).
  • On a plate the 2-across default is a heuristic; some plates want 1 × 2 big markers (the chips show the alternative).
Effort ~2 days
  • markers.autosize() (this page's functions in metres) + tests: 1 d
  • Dialog rewrite, chips, auto buttons: ½ d
  • Face area / fit test probe in Fusion: ½ d
Serial ids
  • A size edit changes the count, so the id block changes length. See the id-block example: existing copies keep their first id; blocks that now overlap are flagged by resolve() and “Number duplicates” fixes them. ArUco Edit should say “count changed 5 → 6: run ArUco IDs”.

Proposal 2 — Count first: today's model, finished

You set: Columns × rows (defaulted from the face's aspect: 1 row on a strip, 2 on a plate; ChArUco 2 / 3 rows; columns = rows × W/H). The marker size is read-only: the largest that fills the face, rounded down to 0.5 mm so it still fits.

Computed: L (or S and L), gap, quiet zone, margins, dictionary, ids. Changing the count changes the size.

Can't fit: it always fits by construction; what can fail is printability — a count that pushes the module under 1.2 mm turns the chip orange, and under 0.6 mm red (the dialog refuses OK). A 1 × 1 “grid” is renamed a single.

Not a rectangle: the same fit test, dropping a column or row until it passes.

This is 80 % of what the add-in does today; the missing 20 % is the rounding, the margins and limits in the chips, the aspect default and the dictionary auto-pick.

Proposal 3 — Pick a layout: the Studio's assistant on a face

You set: nothing, or a filter. The Layout dropdown lists every distinct cols × rows that fits, each at the largest 0.5 mm size that gives it, biggest marker first and badged (largest marker, best fill, most markers). The default pick is Proposal 1's default. Two optional filters: marker size ≥, markers ≥.

Computed: the whole list, by stepping the size down 0.5 mm from the largest that fits to the printable minimum and keeping the first size that yields each new count — the port of ChArUco Studio's suggest_board_grids from an envelope to a face.

Can't fit: cannot happen; the list only holds layouts that pass the invariants. An empty list (a face under 10 mm) says “nothing printable fits”.

Not a rectangle: the fit test runs on every candidate; failing ones are dropped (or shown greyed with “hole”).

Recommendation

Recommended

Build P1, and put P3's list under its size field as a “Layout” dropdown. The size field is the control (R2); the dropdown is how you see what else fits and how you get a particular count without hunting for the size that gives it. Both run the same pure function, so the second costs a day on top of the first. P2 falls out for free (pick an entry, the size is read back into the field).

  1. markers.autosize: layout_for_size, default_sizes, clamp_to_fit, candidates, auto_dictionary in metres, returning a TagSpec plus margins and notes; tested on the five faces here (the numbers on this page become the expected values).
  2. Dialog: Face → Type → Marker size [auto] → Checker size [auto] → Layout (dropdown, ranked) → Dictionary [auto] → First id [auto] → chips; Advanced folds the rest (quiet zone, gap ratio, black thickness / sits, grow cells, rotate, name).
  3. Fit test against the real face for non-rectangles (evaluator samples), shrinking the size until it passes.
  4. ArUco Edit gains the same size field; when the count changes it re-plans serials and says so.

What this does not do: choose where on an L-shaped face the tag goes (sketch a rectangle), or change the black layer's thickness rules (depth_m / raise_m / grow_m stay as they are).

The reference implementation (the code that computed this page, in mm)
def layout_for_size(kind: str, W: float, H: float, L: float, S: float = 0.0,
                    dictionary: str = D4, quiet_modules: float = 1.0,
                    gap_ratio: float = GAP_RATIO, force: Optional[Tuple[int, int]] = None) -> Layout:
    """THE core rule, shared by all three proposals: given the sizes, lay out
    as many markers as fit, centred, and say whether the result is valid.

    single   the black square plus a quiet zone of `quiet_modules` on every
             side must fit in W x H.
    grid     separation = gap_ratio * L (>= 1 module so each marker keeps its
             own quiet zone); cols/rows = how many fit in W - 2 quiet (resp. H);
             leftover is split into the two outer margins.
    charuco  cols/rows = floor(W / S), floor(H / S); the board needs no outer
             quiet zone (each marker sits inside its white square), but the
             marker must leave >= 1 module of white inside the square:
             L <= S * n / (n + 2), which is 0.75 S for 4x4 -- OpenCV's
             tutorial ratio, derived rather than assumed.
    `force` = (cols, rows) keeps a user-chosen count instead of the maximum.
    """
    n = modules_of(dictionary)
    lay = Layout(kind, dictionary, W, H, L, S, quiet_modules=quiet_modules)
    if L <= 0:
        return _fail(lay, "marker size must be > 0")
    Q = quiet_modules * L / n
    if kind == "single":
        lay.cols = lay.rows = 1
        if L + 2 * Q > min(W, H) + 1e-9:
            return _fail(lay, "%.1f mm + quiet zone %.1f mm per side does not fit the %.1f mm short side"
                         % (L, Q, min(W, H)))
    elif kind == "grid":
        s = max(gap_ratio * L, L / n)          # never below one module
        lay.sep = s
        cols = int(math.floor((W - 2 * Q + s) / (L + s) + 1e-9))
        rows = int(math.floor((H - 2 * Q + s) / (L + s) + 1e-9))
        if force:
            fc, fr = force
            if fc > cols or fr > rows:
                return _fail(lay, "%d × %d of %.1f mm does not fit (at most %d × %d)" % (fc, fr, L, cols, rows))
            cols, rows = fc, fr
        lay.cols, lay.rows = cols, rows
        if cols < 1 or rows < 1:
            return _fail(lay, "no marker of %.1f mm fits with its quiet zone" % L)
        if cols * rows < 2:
            lay.notes.append("only one marker fits: this is a single, not a grid")
    elif kind == "charuco":
        if S <= 0:
            return _fail(lay, "checker size must be > 0")
        if L > S * n / (n + 2) + 1e-9:
            return _fail(lay, "marker %.1f mm leaves < 1 module of white inside a %.1f mm square (max %.2f)"
                         % (L, S, S * n / (n + 2)))
        cols = int(math.floor(W / S + 1e-9))
        rows = int(math.floor(H / S + 1e-9))
        if force:
            fc, fr = force
            if fc > cols or fr > rows:
                return _fail(lay, "%d × %d squares of %.1f mm do not fit (at most %d × %d)" % (fc, fr, S, cols, rows))
            cols, rows = fc, fr
        lay.cols, lay.rows = cols, rows
        if cols < 2 or rows < 2:
            return _fail(lay, "ChArUco needs >= 2 × 2 squares; %.1f mm squares give %d × %d" % (S, cols, rows))
        if lay.corners < CHARUCO_MIN_CORNERS:
            lay.notes.append("%d inner corner(s): fine for a strip, weak for a pose board (we suggest >= %d)"
                             % (lay.corners, CHARUCO_MIN_CORNERS))
    else:
        return _fail(lay, "unknown layout %r" % kind)
    if lay.module < MIN_MODULE_MM:
        lay.notes.append("module %.2f mm < %.1f mm: fine on paper, hard for a 0.4 mm nozzle"
                         % (lay.module, MIN_MODULE_MM))
    mx, my = lay.margins
    if mx < -1e-9 or my < -1e-9:
        return _fail(lay, "pattern overhangs the face")
    try:
        aruco_board.check_spec(lay.board_spec())
    except ValueError as e:                      # the OpenCV-validity gate, verbatim
        return _fail(lay, "OpenCV would refuse it: %s" % e)
    return lay


def default_sizes(kind: str, W: float, H: float, dictionary: str = D4,
                  quiet_modules: float = 1.0, gap_ratio: float = GAP_RATIO) -> Layout:
    """Smart default = Zach's rule generalised, rounded to the nearest 0.5 mm,
    then checked; if rounding up broke the fit, step down half a millimetre.

    single    L = 0.7 x short side
    grid      k across the short side (1 on a strip, 2 on a plate):
              k L + (k - 1) gap = 0.7 x short
    charuco   k squares across the short side (2 on a strip -- Zach's L1/L2 --
              3 on a plate, so the board has >= 4 inner corners); the squares
              fill the short side; marker = S n/(n + 2) (0.75 S for 4x4)
    """
    n = modules_of(dictionary)
    short, long_ = min(W, H), max(W, H)
    strip = long_ / short >= STRIP_ASPECT if short else True
    if kind == "single":
        want = (rnd_nearest(FILL * short), 0.0, 1)
    elif kind == "grid":
        k = 1 if strip else 2
        want = (rnd_nearest(FILL * short / (k + (k - 1) * gap_ratio)), 0.0, k)
    else:
        k = 2 if strip else 3
        S = rnd_nearest(short / k)
        want = (rnd_nearest(S * n / (n + 2)), S, k)
    L, S, k = want
    for _ in range(40):                        # step down until it fits as intended
        lay = layout_for_size(kind, W, H, L, S, dictionary, quiet_modules, gap_ratio)
        across = min(lay.cols, lay.rows)          # how many sit across the short side
        if lay.ok and (kind == "single" or across >= k):
            lay.notes.insert(0, "default: %s" % ("0.7 × short side" if kind != "charuco"
                                                  else "%d squares across the short side" % k))
            return lay
        if kind == "charuco":
            S -= STEP_MM
            L = rnd_down(S * n / (n + 2))
        else:
            L -= STEP_MM
        if L < MIN_MODULE_MM * n:
            break
    return _fail(Layout(kind, dictionary, W, H, L, S), "no default fits this face")


def clamp_to_fit(kind: str, W: float, H: float, L: float, S: float = 0.0,
                 dictionary: str = D4, quiet_modules: float = 1.0) -> Layout:
    """Proposal 1's answer to 'too big': the largest 0.5 mm step at or below
    the typed size that still fits (and still is a board for grid/charuco)."""
    n = modules_of(dictionary)
    L0, S0 = L, S
    for _ in range(400):
        lay = layout_for_size(kind, W, H, L, S, dictionary, quiet_modules)
        if lay.ok and (kind != "grid" or lay.count >= 2):
            if (L, S) != (L0, S0):
                lay.notes.insert(0, "clamped: %.1f%s mm does not fit, using %.1f%s mm"
                                 % (L0, "/%.1f" % S0 if S0 else "", L, "/%.1f" % S if S else ""))
            return lay
        if kind == "charuco":
            S = rnd_down(S - STEP_MM) if S == rnd_down(S) else rnd_down(S)
            L = rnd_down(min(L, S * n / (n + 2)))
        else:
            L = rnd_down(L - STEP_MM) if L == rnd_down(L) else rnd_down(L)
        if L < MIN_MODULE_MM * n:
            break
    return _fail(Layout(kind, dictionary, W, H, L, S), "nothing printable fits")


def layout_for_count(kind: str, W: float, H: float, cols: int, rows: int,
                     dictionary: str = D4, quiet_modules: float = 1.0,
                     gap_ratio: float = GAP_RATIO) -> Layout:
    """Proposal 2 (today's model, finished): the count is given, the size is
    the largest that fills the face, rounded DOWN to 0.5 mm so it still fits;
    leftover goes to the margins."""
    n = modules_of(dictionary)
    q = 2.0 * quiet_modules / n
    if kind == "single":
        L = rnd_down(min(W, H) / (1 + q))
        return layout_for_size(kind, W, H, L, 0.0, dictionary, quiet_modules)
    if kind == "grid":
        L = rnd_down(min(W / (cols + (cols - 1) * gap_ratio + q), H / (rows + (rows - 1) * gap_ratio + q)))
        return layout_for_size(kind, W, H, L, 0.0, dictionary, quiet_modules, gap_ratio, force=(cols, rows))
    S = rnd_down(min(W / cols, H / rows))
    L = rnd_down(S * n / (n + 2))
    return layout_for_size(kind, W, H, L, S, dictionary, quiet_modules, gap_ratio, force=(cols, rows))


def candidates(kind: str, W: float, H: float, dictionary: str = D4,
               quiet_modules: float = 1.0, limit: int = 8) -> List[Layout]:
    """Proposal 3: every distinct (cols, rows) that fits, each at the LARGEST
    0.5 mm size that gives it, biggest marker first. The port of ChArUco
    Studio's suggest_board_grids to a face."""
    n = modules_of(dictionary)
    out, seen = [], set()
    if kind == "charuco":
        S = rnd_down(min(W, H) / 2)
        while S >= MIN_MODULE_MM * n * (n + 2) / n:
            L = rnd_down(S * n / (n + 2))
            lay = layout_for_size(kind, W, H, L, S, dictionary, quiet_modules)
            if lay.ok and (lay.cols, lay.rows) not in seen:
                seen.add((lay.cols, lay.rows))
                out.append(lay)
            S -= STEP_MM
    else:
        L = rnd_down(min(W, H) * n / (n + 2 * quiet_modules))
        while L >= MIN_MODULE_MM * n:
            lay = layout_for_size(kind, W, H, L, 0.0, dictionary, quiet_modules)
            if lay.ok and (kind == "single" or lay.count >= 2) and (lay.cols, lay.rows) not in seen:
                seen.add((lay.cols, lay.rows))
                out.append(lay)
            if kind == "single":
                break
            L -= STEP_MM
    if out:
        out[0].notes.append("largest marker")
        most = max(out, key=lambda l: l.count)
        most.notes.append("most markers")
        best = max(out, key=lambda l: l.coverage)
        best.notes.append("best fill %.0f %%" % (100 * best.coverage))
    return out[:limit]


def auto_dictionary(count: int, used: int = 0, bits: int = 4) -> str:
    """Smallest capacity of the chosen family that holds the design's tags
    plus this board plus headroom for serials (same headroom as markers.suggest)."""
    need = used + max(1, count)
    headroom = max(need * 2, need + 10)
    for cap in (50, 100, 250, 1000):
        name = "DICT_%dX%d_%d" % (bits, bits, cap)
        if name in ARUCO_DICTS and ARUCO_DICTS[name] >= headroom:
            return name
    return "DICT_%dX%d_1000" % (bits, bits)

Per-copy ids when a board's count changes

A board's id block is marker_count long and an override stores only the first id (TagSpec.ids = marker_id .. marker_id + count − 1). So resizing the template never edits a copy's record, but it can make two copies' blocks overlap. Computed with markers.plan_serials and resolve:

Rule for all three proposals: a size or count change on a template that has serialled copies re-runs the plan inside the same command (one undo step), and the chip reports “block 5 → 6, 2 copies renumbered”. Variant parts rebuild from the new spec as they do today.
